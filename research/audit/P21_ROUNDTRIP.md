## Findings and precise integration blockers

1. False exhaustion: actual zero-budget PARTIAL owner [0,1,2,3] with zero facts, cursor positive/0, mutated to EXHAUSTED/null/FIXPOINT. Core intake accepts because exhaustion is explicitly producer metadata. Independent verifier rejects missing expected deletion keys. This is a confirmed trust-boundary gap, not a false claim that producer's real exhaustion algorithm failed. No rule-class fixpoint or global pruning from unverified flag.
2. Global attempt reuse: RegisteredLedger keys on (request_id, attempt_id). Different request ID using a-no is registered and actual PROJECTION_NO committed; core rejects batch because attempt ID globally reused. Independent ledger rejects appended pair. Need global ID invariant at registration.
3. Duplicate receipt: actual mock external ACCEPT with receipt mock-receipt-1 under a different attempt is accepted by interface; same receipt token hash in core OBSERVATION rejected. Core rolls back both request and observation; adapter already closed its attempt, so cannot roll back across ledgers. Re-register core request alone succeeds, keeping it pending; duplicate observation still rejected. Need canonical receipt identity and unified transaction before any authority.
4. Origin binding: actual adapter refuses origin mismatch at intake; however core's REQUEST has no trusted expected origin. Starting from real simulator translation, change origin to EXTERNAL plus arbitrary hex receipt reference. Actual core accepts it, independent bare core replay can only classify literal structural NO, never operational ACCEPT. Direct independent adapter bundle replay rejects origin modification against separately supplied registration. Core must bind expected source, maps, capacities and artifact identity in the shared registration; naked origin strings and digest references are not trust.
5. Atomic rollback: malformed second epoch after valid first leaves actual core records empty and owner unchanged; correct batch subsequently accepted. Adapter rejects incorrect origin, incomplete table, duplicate JSON keys, duplicate delivery, malformed/unauthenticated receipt; preserves prior records, marks pending attempt UNKNOWN on invalid first delivery. Malformed JSON attempt closes UNKNOWN, new attempt under same request succeeds. Independent core pending attempt retained; this is not a candidate-frontier completeness proof.
6. Valid roundtrip: 3 projection NOs (one under bounded request, valid structural evidence), one mock external ACCEPT with independently simulated total DFA, one opaque bounded NO (no structural inference). Operational status always INCOMPLETE. 8 closure mutations and 11 adapter-bundle mutations rejected; additionally two core replay batch mutations (attempt/receipt reuse) rejected. No authority from mock callbacks, bounded status or UNKNOWN.
7. Remaining: one transaction/authoritative journal (not present), exact trusted registration and receipt binding, explicit candidate pending/authority state, durable crash recovery, production limits for long traces/full tables, clean CI and live transport owner approval. Do not start P3 on assumption this test bridge is production integration. The driver intentionally expects known gap behavior at pinned heads; after producer fixes, add updated pinned regression expectations and rerun.
