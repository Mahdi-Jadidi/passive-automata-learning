## Single authority and transaction

One in-memory tuple of immutable canonical event bytes under a single reentrant lock with a write-reentry guard. Registration, raw evidence append, response normalization/conversion, and quarantine all pass through one commit boundary. EvidenceLedger is instantiated only as a disposable validator over the projected records plus staged event. No second persistent evidence state, receipt set or attempt registry. Attempt status, mappings, receipts, and core record view are derived from the journal. Attempts globally unique within the entire single-sample journal, across request IDs and origins; no claim of uniqueness across separate processes or journals. A retry requires new attempt ID and the same request target, origin, capacity vector and per-label maps. Caller-supplied request fields are recomputed from the raw sample and registration inputs. No direct public append of REQUEST or OBSERVATION records. Journal snapshot reads are immutable or fresh decoded copies. Ingest errors close only the correctly matched pending attempt as UNKNOWN with a quarantined event; unsolicited or replayed responses cannot close another attempt or append a second observation. All candidates remain pending for the search/authority layer; no incumbent API.

## Serialization

Existing mathematical record schema remains selector-v2/1. New outer format selector-v2-journal/1: object {version,sample_digest,events}. Each event has event and records (list of exact core v1 records). Event variants:
- RAW: raw records only, no request or observation bypass.
- REGISTER: registered={request,capacities,origin,maps}; request as schema v1, capacities null or exact vector aligned with owner roots, maps={positive,negative}, each null or explicit wire-string to positional-ID map. Exactly one matching RAW REQUEST record.
- OBSERVE: request_id,attempt_id,status,receipt_ref,normalized_hex,normalized_sha256,wire_hex,wire_sha256 and one matching OBSERVATION record. Strict JSON parser validates original bytes; pinned adapter validates normalized payload against registered request, capacity and origin. normalized_hex is exact canonical adapter observation wrapper (including request, payload, origin, status, operational:false, scope:NONE). response_digest equals normalized_sha256, not wire_sha256. Original wire bytes stored separately even when noncanonical formatting. Receipt_ref is SHA-256 canonical JSON of receipt string, deduplicated across all successful observations in the journal; core receipt_digest is that reference for EXTERNAL only, null for SIMULATOR. Receipt string identity is a conservative reference convention, not cryptographic authenticity. Normalized block/zeros/free -> group/named_zeros/anonymous_zeros/free_groups. BOUNDED_NO feedback remains opaque/null; no generalization. ACCEPT retains DFA artifact bytes but cannot be operational.
- QUARANTINE: request_id,attempt_id,reason,wire_hex,wire_sha256 and zero or one OBSERVATION record. If and only if a correctly matched attempt was pending, close it as UNKNOWN, no feedback, null receipt. UNKNOWN response_digest is wire SHA-256 or SHA-256(empty bytes) if no wire. Unregistered, mismatched or closed attempt has zero records. No transport/receipt authority.

export() returns canonical full journal; export_records() is its lossless ordered projection of v1 evidence records (not a separate authority). Current independent proof kernel replays this exact projected evidence; it does not yet independently verify the outer provenance/event binding. Request proof agent to extend replay to the outer journal before P2.1 acceptance. False producer EXHAUSTED can pass core validation; independently checked replay must reject it. Never use it alone to prune. Partial closure remains partial.

## Gate limitations

Full-history validation at every commit and per-block table scans are potentially expensive (cumulative quadratic in transaction count), memory-only, no durable recovery or P3 frontier. No independent full-journal provenance verifier yet (v1 projection is independently checked). No network-enabled checkout/CI, no live transport, no external authentication, no operational acceptance. Receipt namespace and actual wire ID normalization before adapter validation remain owner-review decisions. The current path enforces registered maps and provides explicit lookup; normalized response payloads already use positional IDs. No merge, no external learner/baseline changes, no P3. Gate remains pending independent co-review of full journal and integration tests.
