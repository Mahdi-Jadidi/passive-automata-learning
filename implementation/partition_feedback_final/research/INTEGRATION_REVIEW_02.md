## Decision: P2 components accepted for integration review; P2.1 gate remains open
Do not start full P3 search or merge drafts until the following cross-stream boundary is demonstrated.

1. One shared schema: use selector-v2/1 as candidate frozen internal schema for unrestricted ALL_PARTITIONS; explicitly version any change. Keep empty alphabet raw-only and nonempty string tokens. Bounded capacity policy and live protocol are owner gates, not prerequisites to implementing an explicitly structural-only reference search later.
2. Unify registered-attempt interface and typed core ledger using a single transaction/authoritative journal; do not allow separate ledgers to diverge. Core uses globally unique attempt IDs, interface currently keys by (request_id,attempt_id); align on globally unique attempt ID. Bind request, origin, per-label map and capacity to registration; never trust echo. Translate validated normalized payload tables (block/zeros/free) to core feedback (group/named_zeros/anonymous_zeros/free_groups). Preserve exact normalized bytes/digest and receipt artifact references; simulated or unauthenticated ACCEPT must not create operational incumbent. Preserve unresolved candidate even when attempt closed UNKNOWN or observation lacks authority. Align duplicate receipt handling. No live transport modification.
3. Cross-stream roundtrip on pinned actual sources: produce closure/structural records using actual core, route registered fixture responses through adapter into shared ledger, serialize exact ledger, independently replay with proof kernel. Test same-negative components, duplicates, epsilon, Unicode, absent symbols, malformed and replayed receipt, global attempt-ID reuse, mismatched origin, unknown/retry, false EXHAUSTED, bounded exact NO vs projection NO. Verify rollback/no partial append and pending candidate state. Require independent replay to validate raw necessary contractions regardless of completeness; use explicit PARTIAL or INCOMPLETE when resource cap prevents exhaustive replay. Do not let claimed EXHAUSTED authorize pruning absent proof. Long-word tuple materialization and full table scans are scale risks.
4. Add an integration test runner and a CI job or reproducible byte-verified run with actual heads and outputs. Test latest P2, not merely old P1. Keep producer and independent verifier code separate. Draft PRs may be prepared for review but do not merge automatically.
5. Benchmark stream can independently run remaining archived cases, repeat matched budgets, enhanced baseline, and record actual P2 closure/ledger/replay measurements. Label all scope and resource-censored results. Prioritize HDFS/cover path/tiny_choice as fixtures for eventual P3; P1 lower bounds do not solve them.

After P2.1, P3 can begin in unrestricted structural-only/reference simulator mode: E/D disjoint-region branching, rollback DSU, exhaustive fallback, proof-covered residual, restartable frontier and independently verified strict-improvement cutoff. Keep structural status distinct from operational ACCEPT. External end-to-end testing remains blocked by missing owner-confirmed transport/authentication and sanitized real payloads.
