# C006: آیا داده با یک افراز غیر بدیهی سازگار است؟

این ابزار با الفبای معلوم و نمونه‌های برچسب‌خوردهٔ دقیق کار می‌کند. هدفش
تصمیم دربارهٔ **وجود دست‌کم یک افراز سازگارِ الفبا به دو بلوک ناتهی** است؛
زبان هر عامل می‌تواند هر زبان منظم، حتی نامتناهی، باشد. داده باید دو فهرست
`positive` و `negative` از کلمه‌های کامل داشته باشد؛ کلمهٔ تهی را با `""`
می‌نویسیم. نمادهای هر کلمه باید در `alphabet` باشند و برچسب متناقض ورودی
نامعتبر است.

## اجرا از ریشهٔ workspace

نمونهٔ آماده، همان ورودی چهارنمادی‌ای است که هر هفت برش دوتایی آن با گواه
برخورد مثبت/منفی رد شده است:

ورودی JSON نمونه:

```json
{

  "positive": ["acdb", "cabd", "bcda", "dabc"],
  "negative": ["abcd"]

```

برای محدودکردن زمان یا تعداد جواب‌ها می‌توان `--seconds 10` یا
`--max-solutions 2` داد. گزینهٔ `--all` با `--max-solutions` هم‌زمان استفاده
نمی‌شود. ورودی‌های دارای `k`، `q` یا `local_word_cap` رد می‌شوند: تعداد عامل
واقعی از داده معلوم نیست و هیچ کران q روی اندازهٔ زبان عامل‌ها فرض نشده است.

## معنای جواب‌ها

- `found`: دست‌کم یک افراز دوتایی سازگار پیدا شده و projectionهای مثبت و شاهد
  رد هر منفی در خروجی آمده‌اند. جواب اول، تعداد واقعی عامل‌های سامانه را نشان
  نمی‌دهد. اگر `complete=false` باشد، جست‌وجو عمداً با سقف تعداد جواب‌ها
  متوقف شده و یکتایی معلوم نیست.
- `not_decomposable`: گواه کاملِ نبود افراز دوتایی تولید و بازپخش شده است. با
  قضیهٔ coarsening، این یعنی هیچ افراز سازگار با k≥2 بلوک وجود ندارد. این
  وضعیت به معنی نبود هرگونه مدل نیست: افراز تک‌بلوکی همیشه برای دادهٔ با
  برچسب‌های سازگار ممکن است.
- `incomplete`: مهلت یا وقفه پیش از تکمیل جست‌وجو رخ داده است. ممکن است جواب‌های
  جزئی در خروجی بمانند، اما از این وضعیت نمی‌توان نبود جواب یا یکتایی را نتیجه
  گرفت.
- `invalid_input` و `runtime_error`: ورودی معتبر نبوده یا خطای اجرایی رخ داده؛
  هیچ‌کدام گواه علمیِ تجزیه‌ناپذیری نیستند.

در این پروژه، «غیر بدیهی» یعنی دست‌کم دو بلوک ناتهی از نمادهای الفبا؛ لازم
نیست زبان محلی هر بلوک ناتهی باشد. `--all` همهٔ **افرازهای دوتایی سازگار** را
برمی‌گرداند؛ همهٔ افرازها با هر تعداد بلوک را enumerate نمی‌کند. قضیهٔ
coarsening می‌گوید وجود هر افراز k≥2 به وجود یک افراز دوتایی می‌انجامد و
برعکس. این کاهش فقط برای پاسخ بله/خیرِ وجود غیر بدیهی است و k پنهان را
بازسازی نمی‌کند. پس از یک جواب اول هم نباید آن را «تعداد درست عامل‌ها» یا
«افراز نهایی» تفسیر کرد.

## گواه و بازبینی

برای هر افراز، عوامل متناهیِ شامل همهٔ projectionهای مثبت یک شاهد وجود هستند؛
این انتخاب هیچ فرضی دربارهٔ متناهی‌بودن عامل‌های واقعی نمی‌سازد. گواه
`not_decomposable` یا گراف پیوندهای اجباریِ متصل با شاهد هر یال است، یا برای
هر برشِ مؤلفه‌های باقی‌مانده یک منفی و دو مثبت می‌آورد که projection آن منفی
را در هر دو بلوک تکرار می‌کنند. در حالت دوم، پوشش همهٔ برش‌های متعارف کامل
است. verifier هر دو نوع گواه را بازبینی می‌کند.

API بازبینی در `implementation/solver_v5.py`:

```python
import json
import sys

sys.path.insert(0, "results/2026-11-01/partition_identifiability_v6/implementation")
from solver_v5 import solve, verify_certificate, verify_solution

with open("results/2026-11-01/partition_identifiability_v6/implementation/example_manager_candidate_v1.json",
          encoding="utf-8") as f:
    data = json.load(f)
result = solve(data, max_solutions=None)

if result["status"] == "not_decomposable":
    check = verify_certificate(data, result["certificate"])
elif result["solutions"]:
    check = verify_solution(data, result["solutions"][0])
```

`check["valid"]` باید `true` باشد. در حالت `incomplete` هیچ گواه نبود جواب
صادر نمی‌شود. جزئیات قرارداد گواه‌ها و API در
[راهنمای پیاده‌سازی](implementation/README_FA_V5.md) آمده است.

## هزینه و محدودیت‌ها

اگر پس از پیوندهای اجباری `r` مؤلفه باقی بماند، بدترین حالت جست‌وجو
`2^(r-1)-1` برش دوتایی متعارف دارد؛ `--all` و گواه کامل نبود جواب نیز ممکن
است خروجی نمایی بسازند. verifier برای معتبر دانستن گواه، پوشش کامل برش‌ها و
شاهد هر برش را بررسی می‌کند. بنابراین این ابزار برای تحلیل دقیق و داده‌های
متوسط است؛ تضمین زمان چندجمله‌ای نمی‌دهد. گسسته‌بودن گراف پیوندها به‌تنهایی
وجود جواب را ثابت نمی‌کند.

قواعد اصلی تعویض مجاور و نجات درج در پیش‌پردازش فعال‌اند. قواعد افزودهٔ نظری

برای روشن‌کردنشان وجود ندارد؛ جزئیات و اثبات آن‌ها در
