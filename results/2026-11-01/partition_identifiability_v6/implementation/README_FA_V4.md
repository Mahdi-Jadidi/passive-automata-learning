# پیاده‌سازی C006: تصمیم وجود افراز دوتایی

این نسخه برای الفبای معلوم و برچسب‌های دقیقِ کلمه‌های کامل، وجود یک افراز
دوتایی سازگار را می‌یابد یا گواه قابل بازپخشِ نبود آن را می‌سازد. زبان‌های دو
عامل می‌توانند هر زبان منظم، از جمله زبان نامتناهی، باشند. تعداد واقعی عامل‌ها
از داده استنباط نمی‌شود.

## استفاده از API

```python
from solver_v4 import solve, verify_solution, verify_certificate

answer = solve({"alphabet": ["a", "b"],
                "positive": ["a", "b"],
                "negative": ["ab"]}, max_solutions=None)
```

`max_solutions=1` پاسخ وجود را زود می‌دهد؛ در این حالت یکتایی معمولاً نامعلوم
می‌ماند. اگر جست‌وجو به علت وقفه/مهلت پس از یافتن جواب متوقف شود، وضعیت
`incomplete` و خود پاسخ حفظ می‌شود. توقف عادی روی سقف `max_solutions` وضعیت
`found` با `complete=false` دارد. `max_solutions=None` همهٔ افرازهای سازگار را می‌دهد. مهلت، زمان مطلق
`time.perf_counter()` است. هر اجرای ناقص با `complete=false` بازمی‌گردد و
گواه ناسازگاری نمی‌سازد. ورودی‌های دارای فیلد `k`، `q` یا `local_word_cap`
عمداً رد می‌شوند.

## CLI نسخهٔ ۳

python -B -X utf8 cli_v3.py example_manager_candidate_v1.json --all

نمونهٔ ثبت‌شدهٔ `example_manager_candidate_v1.json` هفت برش الفبای چهارنمادی

نجات درج پیدا نمی‌شود. فایل خروجی capture این نمونه در evidence است.

## گواه‌ها و وضعیت

- `found`: دست‌کم یک پارتیشن و تصویرهای مثبت/شاهد رد هر منفی موجود است.
- `not_decomposable`: همهٔ برش‌های مؤلفه‌های پیوندی رد شده‌اند و گواه کامل
  توسط `verify_certificate` بازپخش شده است.
- `incomplete`: جست‌وجو قطع یا مهلت تمام شده؛ دربارهٔ نبود جواب نتیجه‌ای ندارد.
- `invalid_input`: برچسب متناقض، نماد خارج الفبا، ورودی ناقص یا فیلد k/q.

`verify_solution` شاهد خروجی را مستقیم بررسی می‌کند. `verify_certificate`
شاهد هر یال پیوند اجباری، مؤلفه‌ها، پوشش دقیق همهٔ برش‌های متعارف و برخورد
مثبت در هر دو سمت را بررسی می‌کند.

این الگوریتم exact اما نمایی است؛ هزینهٔ پوشش گواه نبود نیز می‌تواند نمایی
باشد. disconnected شدن گراف به معنی وجود افراز نیست. دو قاعدهٔ پیوند اجباری
جدید هنوز در این نسخه فعال نشده‌اند و باید جداگانه اثبات و ممیزی شوند.
