# Runtime and dependency decision

Inspection on 2026-11-14: PowerShell `Get-Command z3,cvc5,minisat,glpsol,highs` returned no executables in PATH. Bundled Python `C:\Users\Mahdi\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe` reports `find_spec` false for z3, pysat, ortools, scipy. This is a scoped PATH/bundled-interpreter check, not proof no installation exists anywhere. No package installed and no solver benchmark was run.

Chosen backend design: independently implemented complete Boolean DPLL over generated CNF using Python standard library only, in a future gated implementation. This is chosen because the checked runtime exists, no external SAT dependency is available in the checked environment, and the slot/equality circuit directly expresses the model with polynomial representation. Not chosen based on previous timings. Python version and solver SHA must be frozen at implementation; there is currently no candidate code or audit. DPLL engineering, proof logging, memory ceilings and meaningful runtime remain OPEN. Complete enumeration can need Bell(m) SAT calls and large memory; no time improvement is promised. No internet access or installation is required for the planned standard-library implementation.

Optional external solver availability can be reconsidered only with a separately documented dependency decision and review. [Z3 official repository](https://github.com/Z3Prover/z3/blob/master/README.md) documents an available Python API; it is not installed in the checked interpreter and is not required by this design. Existing V32/V33 code is literature/model context and later differential oracle only, never an execution dependency of the planned solving path. Independent verifier design and any external proof checker must be disclosed if introduced. Explicit C028 prefix-budget compatibility is OPEN as described in DESIGN_PROOFS_EN.md; design completion does not authorize implementation.
