## Common semantics and envelope

Accept exactly an object with `alphabet`, `positive`, `negative` arrays; alphabet IDs are distinct nonempty strings, and each word is an array of declared IDs. Compare IDs as exact strings, not characters; reject malformed types and undeclared IDs. Deduplicate words within each label by exact sequence equality preserving first occurrence. Let m be alphabet length, P and N the normalized lists. For any block B, H(B) is the set of positive projections onto B and R(B) is the set of negatives whose projection is absent from H(B). The partition criterion is `for each n in N, some B has n in R(B)`; finite H(B) are regular and provide factors. This directly proves both directions, including P empty. The verifier must not trust supplied factors or rejection tags.

The logical certificate object has exactly `version`, `kind`, `claim`, `witness`, `tree`; `version` is `v34-cert-r1`, `kind` is `logic` or `hypergraph`, `claim` is either `OPTIMAL` or `INFEASIBLE`, witness is an array of blocks for OPTIMAL and null for INFEASIBLE. The tree formats are below. These are abstract finite trees, not object graphs: reject cycles, references, duplicate fields, missing or extra fields, wrong types, out-of-range integers, malformed node tags and trailing data. A concrete wire serialization must preserve that unambiguous structure, impose resource limits, and reject parser ambiguities; this serialization and actual checker are OPEN engineering tasks. Verifier failure or exhaustion is REJECT/INCOMPLETE, never a mathematical verdict.

For OPTIMAL validate witness: each block is a nonempty array of distinct declared IDs, every ID occurs exactly once overall, and direct projection comparisons establish full negative coverage. Its k is block count; set threshold t=k+1. For m=0, the sole witness is `[]`, with k=0. INFEASIBLE has no witness and uses t=0 for logic and no objective prune for hypergraph. Outputs are accepted only if the complete corresponding tree verifies. An empty alphabet with N empty is feasible with empty partition; with N nonempty it is infeasible because the conjunction of no factors accepts ε. For m>0 and N empty or P empty every partition is feasible; a singleton partition is optimal. For any P∩N, no partition is feasible. These are consequences, not bypasses: the general tree still applies.

If canonical ordering is ever requested separately, label blocks by first occurrence in alphabet order to obtain an integer vector. Compare vectors lexicographically by integer values component by component, never concatenated decimal strings: e.g. 2 < 10 even though string `10` precedes `2`. Block arrays and IDs are not sorted by text. This certificate does not claim a canonical optimum.

## Logic certificate: fully specified instance-to-CNF and exhaustive refutation

Build F_t afresh for m≥0 using the following deterministic recipe. Variables are identified by structured tuples and sorted lexicographically by tuple category and integer indices; the exact tuple ordering is part of a future wire profile, but is not trusted from a producer. A proof tree may name a tuple directly. Clauses are sets of signed variable tuples; duplicate literals can be removed, and tautological clauses dropped. Empty conjunction is true, empty disjunction false. Constants are simplified as Boolean constants, including when m=0.

1. Variables `y(i,k)` for 0≤i,k<m; impose exactly one k per i using one at-least-one clause and pairwise at-most-one clauses. For k>0 add `¬y(i,k) ∨ OR_{j<i} y(j,k-1)`. Thus occupied slot labels appear in first-occurrence order: any partition has exactly one corresponding assignment, and each assignment is a partition.
2. Define `active(k) ↔ OR_i y(i,k)` for k<m. For each normalized (n,p,k), with u=n and v=p, construct E(i,j) for prefixes as in the original logic design: E(0,0)=true, E(i,0)=E(i-1,0) AND NOT y(index(u_i),k), E(0,j)=E(0,j-1) AND NOT y(index(v_j),k), and E(i,j) is `(NOT x_i AND E(i-1,j)) OR (x_i AND NOT z_j AND E(i,j-1)) OR (x_i AND z_j AND [u_i=v_j] AND E(i-1,j-1))`. Here x_i and z_j select the corresponding symbols in slot k and bracketed equality is a precomputed Boolean constant. Define every named intermediate gate by full equivalence to its stated function, allocating distinct indexed variables for nonconstant gates. Each equivalence g↔f over its listed inputs is encoded by one clause excluding every assignment to those inputs and g for which g≠f; all input combinations are enumerated. When inputs alias, form the truth table over DISTINCT underlying variables, not independent copies. Reuse constants directly. This rule also fully specifies AND, OR and NOT gates and the active gates without reliance on a one-way Tseitin encoding.
3. For each n assert `OR_k (active(k) AND AND_p NOT E(|n|,|p|))`, expressing a single rejecting block per negative. Materialize the intermediate gates by the same truth-table equivalences. Empty OR/AND use the constants above.
4. Assert `sum active ≥ t` directly: if t≤0 add nothing; if t>m add the empty clause; otherwise for EVERY subset T of slots of size `m-t+1`, add `OR_{k in T} active(k)`. This potentially exponential cardinality CNF is intentional and is true exactly when at most m-t slots are inactive.

The equality recurrence follows by considering the last selected symbols of the two filtered prefixes, so E is true iff the projections match. Full equivalences make each gate consistent with its inputs. Consequently F_t is satisfiable iff there exists a compatible partition with at least t blocks. For INFEASIBLE t=0; for OPTIMAL t=k+1 and the separately checked witness supplies the lower bound. A certificate contains no producer-selected CNF: the verifier reconstructs F_t from the input and the above rules.

Tree grammar: `conflict` has no fields except tag; `split` has exactly tag, variable tuple `v`, and ordered children `zero`, `one`. Begin with the empty assignment. At a split, require v to be an existing unassigned F_t variable, then recursively check children under v=0 and v=1 respectively. At conflict require at least one original rebuilt clause all of whose literals evaluate false under the current partial assignment; an empty clause is immediately false. No unit propagation or omitted branch is assumed. Reject conflict without such a clause, a repeated/unknown variable, missing branch, or extra nodes. An implementation may compute residual clauses instead: delete clauses containing a true literal and delete false literals from the others; conflict requires an empty residual clause. Both are equivalent.

Soundness: an empty residual clause rules out all extensions; both values exhaust a Boolean variable, so induction makes every accepted subtree unsatisfiable under its path assignment. Completeness: if F_t is unsatisfiable, build the finite full binary tree by splitting each unassigned variable in fixed tuple order; at each full assignment some clause is false, so mark a conflict leaf (early conflicts may be closed). Thus such a certificate exists for every true claim, assuming the criterion and CNF proof above. A complete assignment with no false clause must be rejected as a purported conflict, exposing any incorrect UNSAT assertion. The tree need not be generated by DPLL, and the verifier does not trust a solver's UNSAT result.

## Hypergraph certificate: full deterministic coverage tree

Independently enumerate every nonempty subset B of declared symbol indices. Recompute R(B) by filtering the actual words and comparing complete ID sequences to every positive projection. These rows are uniquely indexed by B; never accept producer-provided R values. At a node maintain S (initially all symbol indices), U (initially all negative indices), and q (initially 0). Given S nonempty choose the smallest index a in S. The required branch list is **all** subsets B of S containing a, sorted by the numeric bit-vector `(1_{0∈B},…,1_{m-1∈B})` in lexicographic 0-before-1 order. Each child is identified by exactly B; verifier checks the list has exactly these distinct sets, in this order, and recurses with `(S\B, U\R(B), q+1)`. This deterministic symbol choice is a valid specialization of the design's symbol-only branching; all available rows are present so every uncovered symbol has equal degree. No negative-witness branching occurs.

Node grammar: `branch` contains exactly tag and ordered list of `(B, child)` pairs; `uncovered` contains only tag; `bound` contains only tag. If S is empty, accept `uncovered` iff U is nonempty. If U is empty at S empty, this is a feasible completion and must cause rejection of a purported no-better/infeasibility proof. At any node, OPTIMAL may instead use `bound` iff `q+|S|≤k`, since each additional nonempty block consumes at least one remaining symbol. This includes ties and is valid only for proving one optimum. INFEASIBLE never permits `bound`. Otherwise S must be nonempty and a full `branch` is required. For simplicity no other prune is accepted; coverage-union pruning may be added only by a separately specified verifier that recomputes the union and checks a missing uncovered negative.

At every node any completion contains exactly one remaining block B containing a, which is present exactly once in the list; recursion exhausts all partitions. At `uncovered` no symbols remain and at least one negative lacks a rejecting block. At `bound`, no completion can exceed k. Induction establishes that an accepted INFEASIBLE tree has no compatible partition and an accepted OPTIMAL tree excludes every compatible partition with more than k blocks. Conversely, if the claim is true, recursively construct every branch, closing `bound` where allowed and every complete incompatible leaf with `uncovered`. For infeasibility every complete leaf is incompatible; for optimality any complete compatible leaf has q≤k and is closable by `bound`. This includes m=0: optimal k=0 closes by bound; infeasible with N nonempty closes by uncovered. No objective bound is used to justify infeasibility.

## Resource, trust and failure conditions

For logic, let V and L be rebuilt CNF variables and total clause-literal occurrences. The threshold encoding may itself be exponential in m; a full tree has at most 2^(V+1)-1 nodes. Straightforward verification costs O(tree_nodes × L) plus CNF construction and witness projection checks; depth-first working memory is O(L+V), excluding storage of the input, certificate and parser buffering. For hypergraph, row computation is up to 2^m−1 rows times polynomial projection/comparison work in explicit word lengths; the unpruned finite search has at most O((m+1) Bell(m)) nodes, with subset/coverage enumeration and potentially exponential per-node work. Rows require exponential storage if materialized; on-demand recomputation can trade time for space. Both certificate size and output I/O can be exponential or worse as functions of input size; neither is a concise-proof claim. Bounds depend on representation and arbitrary-precision index arithmetic, which must not silently overflow.

The trusted base is schema parser and normalizer, original-instance delivery, exact ID/projection and Boolean/set arithmetic, reconstruction, witness validator, tree parser and checker, plus the soundness arguments above; implementation must be independently audited. Depth-first checking can stream a tree, but must ensure complete input and no trailing material. Resource exhaustion, timeout, interruption, partial tree, malformed data or checker crash never establishes UNSAT, infeasibility or optimality: return INCOMPLETE or REJECT as appropriate. An implementation can report OPTIMAL/INFEASIBLE only after successful end-of-tree and end-of-input. No action on invalid input should be labeled mathematical infeasibility. No implemented checker or experimental validation is asserted here.

Knuth's original [Dancing Links](https://arxiv.org/abs/cs/0011047) provides exact-cover search background; it does not prove the mixed negative-coverage semantics or this certificate. Those claims are established only by the arguments above and remain subject to independent review.

## R1 clarifications for independent review

The hypergraph recursion above is structurally anchored block enumeration: because every nonempty subset of S is available, each remaining symbol has exactly 2^(|S|-1) incident rows, so the design's minimum-degree choice always ties and selects the least remaining symbol. It is not a claim of a fundamentally new partition search or a heuristic advantage; independence from the prior algorithmic family remains OPEN for separate review. No DP is used in this certificate.

For the logic builder, resolve gate naming deterministically as follows. Represent each non-input expression as a rooted ordered syntax tree using the exact parenthesization written in steps 2–3, and use `(n-index, p-index, k, i, j)` for equality outputs; intermediate nodes have tuples consisting of the expression's stable owner (active slot, equality tuple, or negative index) followed by its child-index path in that owner's syntax tree. Treat references to earlier E outputs as input leaves, not inlined subtrees. Construct the expression trees in increasing normalized n-index, p-index, k, i, j, and for each owner assign child-index paths by left-to-right preorder; active owners precede equality owners, then coverage owners. Binary AND/OR parenthesization is left-associated in the written order; zero operands produce the specified Boolean constant and one operand passes through directly. Negation is a unary expression. Represent input names by `(Y,i,k)` and named outputs by owner plus path, with separate disjoint prefixes; `active(k)` and `E` denote the root variable or constant of their owner. Each expression node creates a fresh gate unless constant-folded. Generate its truth-table clauses over distinct referenced variables as specified above, and assert each coverage root with a unit clause, or the empty clause if false. Clause and variable order do not affect satisfaction or the tree check: names are structural tuples and the verifier independently constructs the same named set. Threshold subsets are generated in increasing numeric slot-index sequence. This fully fixes variable identity without trusting an integer numbering or CNF from the certificate producer; a future wire profile must only encode the tuples losslessly and reject duplicate keys and ambiguous numbers.
