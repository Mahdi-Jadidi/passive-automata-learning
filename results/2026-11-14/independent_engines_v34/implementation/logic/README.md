# Standalone V34 logic milestone

`solver.py` uses Python 3.12 standard library only. It does not import prior engines or the separate checker. Run with `C:/Users/Mahdi/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/python.exe solver.py`, providing one UTF-8 JSON request on stdin. It exposes `solve(request)` for already-decoded Python objects; strict duplicate-key, JSON numeric-lexeme, UTF-8 and trailing-data validation occurs at the stdin JSON boundary, so callers of `solve` must enforce those wire properties themselves.

This implementation covers the logic kind only; valid `hypergraph` requests return INCOMPLETE. It produces one optimal witness with an exhaustive refutation or an infeasibility refutation, not counts or canonical witnesses. It validates the proof against a freshly built formula in the same implementation; an independent verifier is still required for audit. CNF and proof may grow exponentially; this is a finite baseline, not a performance claim.

Caps: stdin 8,000,000 bytes; 2,000 CNF variables; 200,000 clauses; 200,000 Boolean-search nodes per threshold; CLI output 8,000,000 bytes. Python recursion, available memory, and serializer depth are additional limits. On caught exhaustion it returns INCOMPLETE; hard process termination may produce no response. `max_nodes` is enforced before entering each search node during each threshold query and again when checking the final tree, and is not C028's `max_candidates`. It also limits SAT discovery, so a search can return INCOMPLETE even when a shorter final proof might exist. The independent search cap also applies. It is not a wall-time or memory limit. The CLI assembles output before writing and returns INCOMPLETE if serialization or its byte limit fails; direct `solve()` returns the in-memory object and does not apply the CLI output byte cap. `max_nodes=0` returns INCOMPLETE for valid supported requests. No cancellation hook or hard wall-clock timeout is implemented; process termination yields no exact result.

Targeted author smoke checks: feasible nonempty alphabet, empty-alphabet infeasibility, zero node limit, duplicate JSON key rejection, and contradictory labels producing a nontrivial tree. These do not replace independent functional and certificate verification. Scope and names follow the frozen R1 documents and gate; hash-bind source after any future edit.
