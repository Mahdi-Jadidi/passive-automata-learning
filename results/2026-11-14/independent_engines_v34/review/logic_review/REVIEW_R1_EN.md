## Findings

**PASS — mathematical certificate strategy and abstract checker, subject to exact reconstruction profile below.** The verifier independently checks a partition witness and original projections. For an optimal witness with k blocks, F_(k+1) is satisfiable exactly when a compatible partition has at least k+1 blocks; its refutation supplies the missing upper bound. For INFEASIBLE F_0 represents the entire compatible family. The threshold subsets are correct: every subset of m−t+1 slots must contain an active slot iff at most m−t slots are inactive. When k=m, t>m creates an empty clause; for m=0, t=1 similarly closes the optimum proof. With m=0 and nonempty N the coverage is an empty disjunction and F_0 has an empty clause. Both empty P and empty N are correctly handled by the stipulated Boolean conventions. Contradiction follows from the criterion, not a special unchecked flag.

**PASS — abstract tree soundness and completeness.** A conflict closes only when an original reconstructed clause is already false under a partial assignment, so no extension can satisfy it. A split on an existing unassigned variable checks both values; induction proves soundness. For an unsatisfiable finite CNF, a complete finite decision tree exists, with a conflict at every full assignment and optionally earlier. Missing branches, unknown/repeated variables, trailing data and malformed trees are rejected. These arguments also cover an empty clause at the root. This is a potentially huge proof, not a succinctness claim. A generator can record both branches and conflict leaves of complete DPLL, but no implementation is shown.

**PASS — alias and logical gate semantics.** Truth tables over distinct underlying variables correctly handle repeated symbol variables and repeated references; constants and zero/one-operand conjunction/disjunction are handled semantically. Full equivalences, provided the actual reconstruction implements them, ensure the prescribed expression values, and the projected partition-to-CNF correspondence holds. Numeric componentwise RGS ordering is correctly distinguished from concatenated decimal strings, though this certificate makes no canonicality claim.

**OPEN — reproducible instance-to-CNF naming and concrete certificate wire profile.** The structural naming clarification is helpful, but the document still permits “unless constant-folded” without a single mandatory rule specifying which operations fold, whether aliases are simplified, and whether an E/active root that reduces to an existing variable receives its own named gate or passes through. These choices can yield different *existing variable sets*: a proof split acceptable against one reconstruction may name an unknown variable against another. The specification also defers the concrete tuple encoding, node and field encoding, duplicate-key detection, integer syntax and framing. That omission does not invalidate the abstract refutation theorem, but prevents independent interoperable producers and checkers from binding a portable proof unambiguously. **Exact repair:** freeze one deterministic expression-lowering and constant-folding policy, including no-fold or exhaustive defined fold, alias treatment, unary/pass-through roots and treatment of constants; enumerate disjoint tuple tags, arities, zero-based indices and syntax-tree ownership/path rules for each gate, especially E boundary/base owners and coverage roots; specify a byte-level canonical or strictly parsed wire format with encoding, legal numbers, duplicate/extra keys, depth/size limits, end-of-input and version behavior. State explicitly which rebuilt formula and variable names the tree refers to. The full reconstructed CNF must be shared by generator and checker, rather than letting either silently choose a valid equisatisfiable variant.

**OPEN — operational milestone and gate scope.** The mathematical proof supports a design-level gate for implementing a **separate V34 one-optimum/infeasibility engine and verifier**, provided the profile above is settled before claiming interoperable certificates and implementation is independently audited. It does not establish an implemented verifier, proof producer, exercised failure handling, checked results, or observed independence. Define the milestone response schema, invalid input and REJECT/INCOMPLETE distinctions, transport behavior on process crash, and generator/checker resource accounting. Return OPTIMAL or INFEASIBLE only after checking the complete proof and end of input; timeout, incomplete tree and crash prove nothing. For practical termination the implementation must either bound resources and return an appropriate incomplete status where possible, or document process-level failure; an uncaught crash cannot guarantee a structured response.

**PASS with cost qualification.** For V variables and L clause-literal occurrences, full trees contain at most 2^(V+1)−1 nodes, and straightforward checking is O(nodes × L) plus formula construction and witness validation, ignoring representation and parser overhead as specified. Threshold enumeration can itself be exponential. A verifier needs at least the storage or streaming access for clause representation, current path and parsing; O(L+V) working memory is conditional on bounded/streaming parser overhead and excludes input and certificate buffers as stated. For L=0 or a zero-node convention, include ordinary constant and node-processing costs (e.g. O(nodes × (L+1))) rather than interpret O(nodes × L) literally as zero. Counts may exceed machine integers.

**OPEN — C028 full contract.** The proposed input keys `alphabet`, `positive`, `negative` belong to the V34 milestone API; authoritative C028 uses `Sigma`, `P`, `N`. The certificate says nothing sufficient to certify C, O, canonical-first witness lists, output serialization or prefix budget. A separately specified and validated adapter and full-contract algorithm remain open. One valid optimum is neither a full C028 result nor physical-ownership identification.

No mathematical counterexample to the stated abstract tree protocol was found. The remaining naming and wire defects are concrete interoperability gaps, not a refutation of SAT certificates or the soundness of a fully fixed reconstruction.
