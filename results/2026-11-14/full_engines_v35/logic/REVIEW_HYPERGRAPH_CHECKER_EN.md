# Independent source review — hypergraph certificate checker

Reviewed bytes: `checker/hypergraph_checker.py` SHA-256 `C97D7555CCDEB7CACC61C6A90DDB93CBCDA985A56449303C419CAB61D71EC920`; `checker/README.md` SHA-256 `598F1C2707E9C378394D55779B50D3EA794F61DE4FEAF2E8F0588BF5152BB5D7`. Scope is read-only source review against frozen V34 R1 and implementation profile, not a runtime audit, formal verification, or approval of full counts.

**Mathematical checker review: no soundness defect found in the inspected paths.** The original separately supplied instance is normalized; `coverage` recomputes each positive and negative projection against the actual block, and unions the rejecting negatives rather than requiring exactly one rejector. Witness validation checks each declared symbol occurs once and union coverage covers all normalized negatives. Tree state starts with all symbols and negatives and q=0. The `bound` tag is checked before terminal/branch logic and is accepted only for OPTIMAL with q+|S|≤k; the feasible S=U=empty leaf is therefore correctly closable by bound. `uncovered` requires S empty and U nonempty. Infeasible claims cannot use bound. For a branch, children are exactly 2^(|S|-1), in numeric 0-before-1 incidence order over remaining sorted indices, each containing S[0]; exact list equality excludes missing, repeated, reordered, extra, and invalid symbols. Coverage is subtracted once per selected block. This gives the required exhaustive search invariant, including overlapping negative coverage, empty alphabet and contradiction.

Only exact Python ints ≥0 are valid numeric indices and max_nodes, so booleans are rejected. Node count is checked before each preorder visit, so max_nodes=0 returns INCOMPLETE after prior request and witness validation. Exact node/object keys are enforced and JSON parsing rejects duplicate keys, extra trailing text, fractional/exponent numeric lexemes, invalid UTF-8 and BOM; `verify` also recursively rejects surrogate code points. `json`, `sys`, and `itertools` are the only imports; no candidate or old engine is imported. Resource failures and caught cancellation return INCOMPLETE. Direct already-decoded Python calls cannot detect JSON duplicate keys or original numeric lexemes, as noted in README.

**Concrete documentation/API mismatch (low severity):** README says `strict_load(raw_bytes)` itself enforces Unicode requirements before `verify`, but `strict_load(b'"\\ud800"')` returns a Python string containing an unpaired surrogate: surrogate rejection occurs only on the later `verify`/`validate_value` call. The CLI composes both and therefore rejects that value; the public `strict_load` function alone does not. Correct README to say Unicode-scalar validation happens in `verify`, or explicitly validate within `strict_load` if that function is intended as the standalone strict interface. No mathematical ACCEPT bypass was found in the composed verifier from this issue.

Independent tests, malformed-tree adversarial corpus, limits and cross-engine integration still need audit. This source review does not certify C/O, canonical witnesses, or algorithmic independence of the hypergraph generator.
