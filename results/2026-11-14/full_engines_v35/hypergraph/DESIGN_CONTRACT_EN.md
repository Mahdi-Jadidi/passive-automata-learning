# V35 hypergraph full-output design and contract — review gate

**Proposed, not implemented or tested.** User authorizes implementation of this standalone engine despite the still-OPEN fundamental novelty/distinction of its search. This is an Algorithm-X-style mixed-cover enumeration, structurally least-symbol anchored block recursion, not a claim of a fundamentally new algorithm, advantage over earlier engines, or physical identification. No prior solver, RGS generator, subset DP, graph or hybrid engine is imported, invoked, dispatched to, or used as fallback. Prior mathematical predicates and independently reviewed certificate specification are reused. Independent design and output-contract review precedes implementation.

## Interfaces and validation

`solve(data, *, max_candidates=None)` targets observable behavior of frozen `results/2026-11-11/exact_foundations_v28/implementation/reference.py` (SHA-256 `5F60B27447B37EC07F1FD6BCE75BE6199B898573D4B32E90413E900E3A615A94`), not the historical SPEC's `Sigma/P/N` names. Input is exactly a Python dict with keys `alphabet`, `positive`, `negative`; validation, validation order, exception-to-reason strings, acceptance of Python strings including nonempty Unicode surrogate-containing strings, and first-occurrence duplicate normalization match that executable `_normalize`. Words and alphabet are lists; IDs are opaque nonempty strings and words may be empty or contain repeated IDs. `max_candidates` is None or exact `int` ≥0, not bool, checked before data, with identical invalid result and reason. The return is the reference's exact dict keys, optional `reason`, statuses and values. Exception and resource semantics follow the frozen reference where implementable; a caught `KeyboardInterrupt` or `MemoryError` gives its same INCOMPLETE result and reason; no partial exact outputs are returned.

`certify(instance, *, max_nodes=None)` is a **separate**, explicitly V34-profiled JSON-compatible milestone API. It uses the V34 `alphabet/positive/negative` envelope, accepts only Unicode scalar strings, independent limits and responses as in `certification/IMPLEMENTATION_PROFILE_R1_EN.md` SHA-256 `F99B909B5D52A5FAD2FF9FD94896B21A147D00B520E5A5A16C66721D130580D4`, and produces one optimal partition with proof or an infeasibility proof. An independent checker must be authored separately and rebuild coverage from original input; solver-generated certificates are not themselves independent checks. This milestone certificate does **not** certify C, O, uniqueness, canonical witness order or full output. `solve` and `certify` are separate calls; no implicit claim that C028's Python string domain and scalar-only certificate wire domain coincide.

## Finite mixed-cover search and proof

After input validation normalize duplicate full words preserving first occurrence. For every nonempty B⊆Σ, form one row with symbol columns B and negative tags R(B)={n: projection(n,B) absent from H(B)}, H(B) the positive projections. Symbols require exactly one selected row; negatives require at least one tag. Rows with no tags remain. Every compatible partition corresponds to exactly its row set: necessity because each factor accepts H(B); sufficiency using finite regular languages H(B). Each negative needs one block rejecting it against every positive, not separate blocks per positive. Overlapping negative tags are allowed and never generate extra choices. Declared but absent IDs remain covered.

Search state is Q selected disjoint rows, S uncovered symbols, U uncovered negatives. Initially Q empty, S=Σ, U=N. If S empty, emit Q exactly if U empty. Otherwise, candidate rows are all nonempty subsets of S; choose a deterministic uncovered symbol of minimum incident-row degree, tie by alphabet order, and branch on every row B containing that symbol in a fixed deterministic subset order; recurse on Q∪{B}, S\B, U\R(B). All symbols have degree 2^(|S|-1), so choice is always the least alphabet index in S: this is anchored block enumeration, explicitly not a novel search principle. Optional prune only if some U negative occurs in no available row; no optimum bound is permitted in full search, because C and canonical first compatible witnesses require all compatible leaves. Each target partition has exactly one block containing the chosen symbol and hence one path; this remains true after deterministic choices and sound union prune. All leaves finite; each compatible partition is emitted once. For m=0 the sole empty partition is compatible iff N empty; for m>0 and disjoint labels full Σ is a feasible block; contradictory labels are incompatible. P=∅ or N=∅ with nonempty alphabet makes all partitions compatible.

For each emitted partition compute its canonical RGS **integer tuple**, labeling blocks in first alphabet occurrence order. Increment unbounded C, maintain the numerically lexicographically smallest two compatible tuples. Track k* and O: higher k resets O and the optimum top-two list; equal k increments O and inserts among smallest two. Exhaustion gives exact outputs regardless of search order. A retained witness contains `rgs` integer list, `blocks` in canonical order with IDs in alphabet order, `factors` as first-occurrence-ordered distinct positive projections per block, and `negative_rejected_by` as the first canonical block index rejecting each first-occurrence-normalized negative. Recommendation equals first optimal witness; status is `UNIQUE_COMPATIBLE` iff C=1 else `AMBIGUOUS`; `optimal_unique` iff O=1. With no feasible partition return `INCOMPATIBLE`, C=O=0, witness lists empty and other mathematical fields null, exactly as reference. Replay each retained witness, factors and rejection indices before returning; detected replay failure gives reference ERROR and its reason.

## Candidate budget — proposed observational equivalence, not prefix execution

The reference first validates budget, then data, then returns immediate INCOMPATIBLE for contradictory labels even at budget 0. Otherwise it enumerates all Bell(m) canonical candidates, checking the cap immediately before inspecting each. Since it returns only an all-null INCOMPLETE with fixed reason whenever cap < Bell(m), and otherwise performs full evaluation, propose calculate Bell(m) independently by a capped integer recurrence (stop only once a mathematically sound lower bound exceeds the nonnegative cap). If cap < Bell(m), return exactly reference `_blank('INCOMPLETE','candidate budget exhausted')` without running the search; if cap ≥ Bell(m) or cap None, perform full mixed-cover search. This has the **same successful observable output** for deterministic unlimited-resource reference execution, including Bell(0)=1, cap 0 and contradiction shortcut, provided replay and all output/error rules match. It does **not** inspect the reference's canonical prefix and does not reproduce timing, work, side effects, host interruptions or resource-exhaustion outcomes. Do not describe it as literal C028 prefix traversal. Independent reviewer must decide whether observational budget compatibility satisfies the user's requirement before implementation. Bell computation itself may be interrupted and return the reference resource-interruption result; no exact status is claimed on interruption.

## Separate certificate production and verification

For `certify`, validate strict V34 instance and limit, reconstruct rows independently from raw instance, and determine one optimum or infeasibility via finite mixed-cover search. Construct `v34-cert-r1` `kind=hypergraph` tree exactly per R1 spec and implementation profile: at S nonempty branch on all subsets containing least index in full length-m 0-before-1 incidence-vector order; each child stores increasing index array B. State q is selected-block count. For OPTIMAL, a `bound` leaf is accepted first exactly when q+|S|≤k; for INFEASIBLE bounds are forbidden. `uncovered` is allowed only at S=∅ and U≠∅; otherwise a terminal leaf is rejected. Rebuild R(B) from normalized trusted instance, not producer tags. A feasible witness directly checked supplies lower bound k; complete bounded tree excludes all better partitions. Infeasible tree exhausts all partitions with uncovered terminal negatives. This includes m=0, where an empty feasible witness closes by bound at k=0, and empty-alphabet negative closes by uncovered. At each node every partition has exactly one block containing the least symbol; bound is valid because each remaining block consumes at least one remaining symbol. These facts prove soundness and completeness of finite abstract certificates, not successful execution.

Certificate request and result precisely follow the profile's solver object and response fields: `instance`, `kind` = `hypergraph`, `limits` = `{max_nodes: M}`; result status INVALID_INPUT/INCOMPLETE/OPTIMAL/INFEASIBLE and certificate null unless exact. `certify` is a convenience name for this request-driven API, to be specified identically in implementation. Tree node count is DFS preorder including root, checked before entering each node; M=0 yields INCOMPLETE. Enforce node/resource limits during construction, not only after it; any caught resource interruption yields INCOMPLETE, no partial exact certificate. Self-check completed proof before exact response, but a separately authored checker and independently delivered original instance remain necessary for independent verification. Strict JSON parsing and duplicate keys, full consumption, arbitrary exact integers, nonfinite/Unicode rejection and optional documented caps follow the frozen profile, including its REJECT versus INCOMPLETE distinctions for the checker. Hard termination may yield no response.

## Costs and review conditions

Rows: 2^m−1, up to O((m+|N|)2^m) incidences plus input-length-dependent exact projection work; alternatives may recompute without retaining all rows. The unpruned tree has at most (m+1) Bell(m) nodes, since every node extends to a full partition and each full partition has one path of at most m+1 nodes. Negative-union pruning only removes nodes. Per-node subset/coverage work, arbitrary-precision C and O and tuple comparison, row storage, witness construction, factor serialization, budget preflight and independent certificate generation/verification must be accounted separately. Certificate trees and explicit output can be enormous; no polynomial-size or practical runtime guarantee. Full output has no independently checkable count certificate in this design. Exact results only after exhaustion; caught interruptions cannot supply mathematical fields.

Before implementation reviewer must audit executable-reference field/reason fidelity, Bell preflight assumptions, first-two tuple ordering and witness serialization, boundary cases, search uniqueness, separate API and strict profile, and whether user-authorized structural overlap is accurately disclosed. Review bytes by hash; do not modify frozen V34 evidence. No benchmark, deployment or public default change is authorized by this design alone.
