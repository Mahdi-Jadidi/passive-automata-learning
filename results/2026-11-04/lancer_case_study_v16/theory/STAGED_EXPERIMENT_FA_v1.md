# C016 — نردبان فرض‌ها و آزمایش نخستِ پیشنهادی

پیشنهاد پژوهشی، نه پروتکل اجراشده یا source clearance. مقاله کامل در
PAPER_ALIGNMENT_FA_v1.md با شناسه‌های F01–F20 بررسی شده است. تمام موارد
زیر تا مشاهدهٔ کد/داده «فرض/پیشنهاد» هستند، نه واقعیت اضافه‌شده به مقاله.

## مرحله صفر: قرارداد داده قبل از افراز

فایل خام، نسخهٔ collector/simulator، seed، run/episode boundaries، action
schema، parameter order، reset و برچسب هر event-end را ثابت کنید. صرف PDF
برای بازسازی بدون‌حدسِ داده کافی نیست. هر توکن action/value را یک نماد
کامل بگیرید؛ جدول ID برگشت‌پذیر بسازید. outcome و true state ورودی مدل
نباشند. نرمال‌سازی subnet/IP/exploit مطابق F09 باید نسخه‌دار باشد.

قبل از یادگیری، شمار توکن‌ها، طول برحسب event/step/token، P/N، conflict
یک word با دو outcome و leakage را گزارش کنید. conflict می‌تواند از
resetِ حذف‌شده، پارامترِ حذف‌شده یا حالت پنهان بیاید؛ نباید با حذف دلخواه
رکوردها به‌عنوان دادهٔ بی‌نویز جا زده شود. اگر raw داده موجود نیست، نخستین
تحویل همین مانع provenance است، نه دیتاست ساختگی با ادعای بازتولید مقاله.

## آزمایش نخست: دو میزبان، فقط network-validity، گروه معلوم

این زیرحالت در F18 مقاله بررسی شده و از all-monitors محدودتر است.
اما تنها در صورتی آغاز شود که کد قابل ممیزی تأیید کند outcome هر رویداد
میزبان از تاریخچهٔ محلیِ مشخص‌شده قابل محاسبه است. اثر DRS، کشف/session،
NoOp و Remove را باید دقیق مشخص کرد؛ صرف خاموش‌کردن دو مانیتور سراسری
F14 اثبات محلی‌بودن همهٔ وابستگی‌ها نیست.

۱. روی همان raw traces، baseline تک‌مدلی با تاریخچه/برچسب outcome مقاله
بسازید؛ تبدیل اصلیِ action+parameter و نسخهٔ atomic event tuple را جدا
نام‌گذاری کنید. هیچ outcome آخرین‌رویداد را «اجرای ممنوع» معرفی نکنید.
۲. baseline محلیِ معلوم‌گروه را با تمام رویدادهای مؤثر بر میزبان بسازید؛
برای هر رویداد محلی، label همان outcome واقعیِ آن رویداد است. Removeِ blue
روی میزبان مربوط باید در تاریخچهٔ همان میزبان بماند. حذف global event
فقط پس از اثبات بی‌اثری مجاز است؛ در غیر این صورت فرض محدود رد شده است.
۳. هنگام ارزیابی event روی j، از مدل j پس از اعمال ورودی محلی پیش‌بینی
بگیرید؛ برای outcome همان رویداد خروجی همهٔ مدل‌ها را AND نکنید.
این baseline partition-known، پژوهش دربارهٔ شرطی‌کردن خروجی است، نه اجرای
حل‌گرِ C015 روی افراز مجهول.
۴. روی مجموعهٔ یکسان و split برحسب run مستقل، accuracy/failure recall،
تعداد حالت میانی/نهایی، زمان و حافظه را مقایسه کنید. prefixهای یک run
میان train/test پخش نشوند. truncationهای طول‌ها از منابع یکسان باشند تا
مقایسهٔ افق با تغییر محتوا مخلوط نشود. خطای rare kill-chain جدا سنجیده شود.

موفقیت این مرحله فقط می‌گوید baseline با فرض محلیِ بررسی‌شده قابل ارزیابی
است و شاید هزینه را کم کند؛ یکتایی یا مالکیت فیزیکی ثابت نمی‌شود. شکست
فرض نیز نتیجهٔ معتبر است و باید با دو تاریخچهٔ محلیِ یکسان/خروجی متفاوت
یا مسیر علت از source ثبت شود.

## مسیر جدا برای آزمودن مستقیمِ نظریهٔ حاصل‌ضرب فعلی

اگر واقعاً هدف C015 باشد، می‌توان یک target **جدید و صریحاً مشتق‌شده**
تعریف کرد: برای هر host آخرین outcome محلیِ مشاهده‌شده را نگه داریم و
در نقاطی که همهٔ hostها حداقل یک مشاهده دارند، AND آن‌ها را label کنیم.
برچسب از metadata واقعی ساخته می‌شود، اما این هدف با label مقاله متفاوت
است و نباید بازتولید مقاله نامیده شود. برای نقاط پیش از اولین observation
هر host هیچ مقدار اولیهٔ حدسی تعیین نشود.

اگر علاوه بر آن ثابت شود خروجیِ محلی تابع فقط تاریخچهٔ محلی است و
دینامیک میزبان‌ها مستقل است، هر عامل می‌تواند acceptance «آخرین outcome
خودش» داشته باشد؛ AND آن‌ها دقیقاً مدل مستقل را می‌دهد. آنگاه projection
criterion و gate برای **این هدف جدید** قابل استفاده‌اند. بدون آن اثبات،
تغییر label کمبود استقلال را اصلاح نمی‌کند. این مسیر اختیاری است، نه
پیشنهاد تغییر پنهانی برچسب دادهٔ مقاله.

## برداشتن فرض‌ها، یک‌به‌یک و با معیار شکست

| مرحله | فرض اولیه | تغییر بعدی | آزمون/مثال نقضِ تعیین‌کننده |
|---|---|---|---|
| A | توکن‌سازی و reset معلوم | پارامتر/شناسه کمتر | conflict یا افزایش خطای holdout پس از abstraction؛ متن pp۵–۶ نیاز به exploit class را گزارش می‌کند |
| B | گروه میزبان معلوم و local-outcome وابسته به local-history | افراز مجهول | نخست theorem شرطیِ خروجی؛ C015 AND-label بدون اثبات کافی نیست |
| C | بدون global monitors و وابستگی شبکه‌ایِ اثبات‌شده حذف‌شدنی | DRS، session یا global monitor | دو تاریخچه با local-projection برابر ولی outcome محلی متفاوت؛ وابستگی واقعی مانع است |
| D | event tuple اتمی با target معلوم | action/value توکن‌های جدا | action مشترک یا hostname مشترک؛ معنای مالکیت توکن عوض می‌شود |
| E | یک آغاز/context معلوم | resetهای متعدد یا state بین episode | یک word تکراری با outcome مخالف، یا نیاز به initial-context condition |
| F | الفباهای مجزا | رویداد مشترک/monitor overlap | مدل product همگام/اشتراک الفبا و اثبات تازه، نه کاربرد خودکار gate قبلی |
| G | فرض‌ها و K واقعاً معتبر | K نامعلوم و truth مخفی | یک‌بلوکی همیشه جایگزین؛ sample-finest با truth یکی نیست |
| H | دادهٔ بی‌نویز و تعیین‌پذیر | partial observation/stochastic effects | تعارض label؛ ثبت نرخ/ریشهٔ ابهام، نه ساخت منفی یا حذف گزینشی |

**مثال نقض محوری** y موفق، x ناموفق، y موفق را حفظ کنید: P={y,yxy}،
N={yx} حتی برای دو دستگاهِ بی‌حالت مستقل، افراز x|y را در مدل ANDِ
زبان رد می‌کند. پس تغییر target ممکن است از تغییر الگوریتم مهم‌تر باشد.
افراز red|blue نیز Remove و exploit روی یک host مشترک را نادیده می‌گیرد؛
هم‌تأثیری به معنی مالکیت مشترک فیزیکی نیست، ولی استقلالِ roleها را رد می‌کند.

## ادعاهای مجاز و غیرمجاز

مجاز: سازگاری/ابهام نمونه در یک کلاس مدل صریح؛ دقت روی split مشخص؛
تفاوت حالت میانی RPNI روی دادهٔ یکسان؛ معلوم‌گروه یا مشتق‌شدن target با
نام روشن؛ فرض ردشده با witness. غیرمجاز: دقت۱۰۰٪ holdout یعنی هم‌ارزی
زبان؛ failure-action یعنی trace غیرقابل اجرا؛ monitor votes یعنی عوامل
مجزا؛ میزبان‌های ذکرشده یعنی Kِ زبانِ معلوم؛ عملکرد synthetic جدید یعنی
بازتولید CybORG یا بازیابی سخت‌افزار.

پیشنهاد فعلی هیچ منفی جدیدی نمی‌سازد، کد بیرونی اجرا نمی‌کند و source
data موجود نبودن را پنهان نمی‌کند. صورت مسئلهٔ افرازِ مجهول برای هدف
چندخروجیِ paper-faithful یک مسئلهٔ بازِ مشخص است؛ نخست باید قرارداد
مشاهده و استقلال را روی واقعی‌ترین زیرحالتِ قابل دسترس احراز کرد.
