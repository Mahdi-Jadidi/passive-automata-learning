Abstract.We show how to use passive automata learning to infer mod-
els of attacker-defender interactions in cybersecurity. By treating system
event logs as words in a formal language, we can apply the RPNI al-
gorithm to infer minimal deterministic finite automata from observed
traces. We evaluate this approach through a case study on the Cyber
Operations Research Gymnasium (CybORG), a widely-used simulation
framework for training defensive agents using machine learning. We an-
alyze the structural properties of the inferred automata and assess their
empirical fidelity with respect to the semantics of CybORG. Our results
show that accurate formal models can be learned from a relatively small
number of traces, suggesting a promising path toward more automated
and data-driven approaches to cybersecurity.
1 Introduction
Reinforcement learning (RL) [12] is a promising approach to cybersecurity, en-
abling defensive agents to be trained simply by interacting with an environment,
without requiring explicit models of system dynamics or attacker behavior. How-
ever, RL is notoriously data-hungry [4] and typically requires millions of interac-
tions during training—far beyond what is feasible using live systems or emulated
environments. As a result, most RL-based approaches to cybersecurity rely on
simulators that approximate the state space and transition behavior of the un-
derlying system using more efficient representations. Building such simulators is
itself a major challenge, requiring domain expertise and significant engineering.
This state of affairs motivates a natural question:can simulators be con-
structed automatically from data?Thatis,ratherthanhavingtomanuallydesign
and build complex simulators, one might hope to infer formal representations
directly from system traces. Automata learning offers a principled foundation,
including techniques for synthesizing finite-state models that are guaranteed to
be consistent with observed behaviors. Even when learned models do not capture
every aspect of a system’s behavior, they can nevertheless provide high-fidelity
approximations that are sufficient for downstream tasks like RL training.
This paper presents a case study in using automata learning to infer formal
models of networked systems. We show how to interpret system event logs as

the behavior of the original system, but run much faster in practice.
Overall, this paper makes the following contributions:
–We show how to model event logs as words in a formal language, enabling
the use of passive learning for inferring formal models of system behavior.
–We develop heuristics to help scale up learning to systems of realistic size.
–We conduct a case study using CybORG and analyze the size and accuracy
of the inferred models.
Related Work.The idea of using automata learning to infer models of networked
systems has been explored in several pieces of prior work. Alembic automates
model inference for stateful network functions, combining passive traffic analysis
with symbolic execution to discover complex state transitions [9]. Prognosis uses
active learning to build models of protocols like TCP and QUIC, which can then
be used to test implementations [2]. Finally, recent work by Moeller et al. adapts
Anguilin’sL∗ [1] algorithm to NetKAT, producing symbolic models which can
then be used to verify reachability properties [8].

2.2 Automata Learning
Automata learning [5] is a branch of machine learning dedicated to inferring
formal grammars or automata from observational data. In the case of regular
languages, the objective is typically to learn a minimal deterministic finite au-
tomaton (DFA) that accurately models a target language over a given alphabet.
Due to its theoretical significance and practical applications in formal verifica-
tion, synthesis, and system analysis, automata learning has drawn substantial
and growing interest from the verification community [3,6,13].
In the literature, automata learning techniques are commonly distinguished
by the nature of the information available to the learner. The first paradigm,
active learning, involves an interactive process where the learner dynamically
queries a “teacher” or “oracle” (e.g., as in Angluin’sL∗ algorithm [1]). In contrast,
the second paradigm, passive learning, does not involve such an interaction.
Here, the learner is presented with a static, fixed dataset of labeled examples
from which it must infer the underlying language. This paper focuses on passive
learning, utilizing system event logs to infer a DFA. In the cybersecurity context,
the dataset consists of traces of events initiated by offensive (red) and defensive
(blue) agents.
The passive learning task is formally defined by two disjoint sets: a set of
positive examplesS + ⊆L(valid interaction sequences) and a set of negative ex-
amplesS − ⊆(Σ ∗ \L)(invalid sequences). The learner seeks a DFAAsuch that
S+ ⊆L(A)andS − ∩L(A) =∅. The Regular Positive and Negative Inference
(RPNI) algorithm is the foundational state-merging method for passive learning
of regular languages in polynomial time [10]. It starts from a Prefix Tree Accep-
tor (PTA) built from positive examplesS+. It generalizes by deterministically
traversing the PTA’s states in a fixed order, attempting to merge each candidate
state with an earlier compatible state. A merge is accepted only if the resulting
DFA remains consistent with the negative examplesS−; otherwise, the merge is
undone. This process yields a DFA consistent with the data.

4 Case Study: Learning Models of CAGE Challenge 2
This section reports on our experiences using passive learning to infer a state-
machine model of CAGE Challenge 2 [7]. In CAGE 2, agents interact in a small
enterprise network modeled using CybORG, with red and blue performing ac-
tions like the ones discussed in the preceding section. The network topology has
three subnets with user hosts, enterprise servers, and operational hosts, as shown
in Figure 3. The red agent starts with a presence on one of the hosts in the user
subnet and seeks to impact a designated server in the operational subnet; the
blue agent starts with a presence on a host in the enterprise subnet and seeks
to prevent red from achieving its goal. Additionally, green agents may generate
non-malicious traffic from user host, making it harder for blue to detect red.
We augmented CybORG to extract simulator traces. The trace data includes
theactionschosenbyagents,theobservationsaboutthestateprovidedtoagents,
as well as information about the true state of the simulation (e.g., whether red
has a session, blue has a decoy, etc.) that cannot be perfectly known by either
agent. We then collected traces over a long training run for a blue agent. Traces
collected early in the run reflect the logic of a naive agent, with many invalid
steps, while traces collected later reflect the logic of a more refined agent. For red,
we used two standard agents: B-line, which attempts to move directly toward
the target host, and Meander, which follows a random path.
To prepare CAGE 2 traces for RPNI learning, we apply several preprocess-
ing steps. First, we map raw subnet identifiers expressed in CIDR notation (e.g.,
10.0.128.112/28)tosemanticnamessuchasUser,Enterprise,andOperational,
reducing the alphabet size and improving generalization across network config-
urations. Second, we translate IP addresses to hostnames, to ensure a consis-
tent naming for hosts. Third, we augment action symbols with an exploit class
(e.g.,SSHBruteForce,Eternalblue), to resolve non-determinism and ensure
that identical inputs yield identical outcomes.
After preprocessing, we converted 5000 raw CAGE 2 traces into our format.

actions, and a heuristic agent that biases exploration toward the natural attack
progression following the kill chain (DiscoverSystemsandDiscoverServices

each trial, we generated 200-step traces and produced shorter variants (100, 50,

5 Conclusions
This paper presented a framework for modeling cybersecurity agent interactions
as a language inclusion problem, using CybORG and the CAGE Challenge 2 as
a case study. By transforming raw CybORG logs into formal languages where
strings represent event histories ending in successful actions, we demonstrated
how passive automata learning techniques, specifically RPNI, can extract in-
terpretable behavioral models from observed traces. The learned deterministic
finite automata capture the implicit rules governing attacker-defender dynamics,
providing both a mechanism for strategy analysis and a foundation for anomaly
detection. Our results show that even limited observational data can yield mean-
ingful automata models, creating a pathway for automated inference of simula-
tors as well as applications of formal methods in the future.

A The BabyCyborg Environment
To better assess the effectiveness of automata learning in a controlled envi-
ronment, we developed a CybORG-like simulator called BabyCyborg. It uses a
simplified four-host topology with red and blue that use a streamlined set of ac-
tions. This appendix presents BabyCyborg in detail, and discusses some results
from further experiments.
A.1 BabyCyborg Actions
The red agent may act on any host usingDiscoverNetworkServices(DNS),Ex-
ploitRemoteService(ERS),PrivilegeEscalate(PE), orImpactactions, or it may
execute a global actionDiscoverRemoteSystems(DRS) to discover remote hosts.
Meanwhile the blue agent may eitherRemovered’s privileges at a host or execute
aNoOpaction, which observes the system state without altering it. Agents re-
ceive a single observation—the success or failure of their action—which provides
partial information about the underlying system state and enables the design of
heuristic attacker behaviors. Action success is determined by a set of monitors
that encode the system’s logic. We use four host-specific network validity mon-
itors to enforce each host’s state machine. This restricts red’s actions (e.g., PE
fails unless preceded by a successful ERS), while blue’s actions always succeed
under these monitors. To introduce constraints on blue, we add two additional
monitors:blue_action_limit, which causes blue’s fourth consecutive successful
action to fail, andred_impact_blocks_blue, which blocks blue’s next action fol-
lowing a successful red Impact. Each monitor independently votes on whether
an action should succeed, and an action fails if any monitor votes to fail, yield-
ing a deterministic transition system whose behavior is fully defined by these
conjunctions and is therefore amenable to learning via RPNI.

We adopt an incremental learning approach, training the DFA using RPNI on
progressively larger subsets of training traces and evaluating performance at each
checkpoint.Achieving100%accuracyontheheld-outtestsetisastrongindicator
that the learned automaton has captured the system’s behavior. Additionally,
when the number of states stabilizes and no longer changes with additional
training data, this suggests convergence to a stable automaton. To evaluate the
learned automaton, we measure accuracy by comparing its predictions against
held-out test traces. For each step in a test trace, we strip away the success label
and feed the action sequence to the learned DFA. The DFA predicts whether the
action should succeed (accepting state) or fail (rejecting state), and we compare
this prediction to the actual success value recorded in the trace. Accuracy is
computed as the fraction of correctly predicted steps across all test traces.
Finally, to evaluate whether RPNI can recover system logic from interaction
traces, we begin with a minimal experimental setup consisting of a single host.
We then incrementally test learning on more complex systems by increasing the
number of hosts and/or including additional monitors.

A.4 All Hosts All Monitors
Lastly, we consider the most complex configuration of BabyCyborg: the four-
host topology with all monitors enabled. This setup combines the full network
complexitywiththecompletesetofbehavioralconstraints,representingthemost
challenging learning task in our evaluation.
In this setting, evaluation using purely random traces becomes problematic.
Each additional host introduces five new actions for red (DRS, DNS, ERS, PE,
Impact), but only one additional action for blue (Remove). With four hosts, red
therefore has 20 possible actions, while blue has five (Remove_0, Remove_1,
Remove_2, Remove_3, and NoOp). As a result, the probability that red ran-
domly executes a coherent sequence of actions on a single host—without blue
interrupting via a Remove—decreases dramatically.
To mitigate this issue, we construct a combined evaluation set consisting
of 500 heuristic traces and 500 random traces. The heuristic agent operates
as follows: it selects a random host to start from and, with 80% probability,
follows the kill-chain sequence on that host (DRS→DNS→ERS→PE→
Impact). With 10% probability, it performs a random action on the current host
(resuming the kill chain afterward), and with 10% probability, it switches to a
different host and restarts the sequence. This mixed strategy improves coverage
of rare but semantically meaningful execution paths in the evaluation traces.

and the heuristic agent with 80/10/10 probabilities. For each agent type, we

A.5 Discussion
The Need for Heuristic Agents.As system complexity increases, uniform random
exploration becomes insufficient for both training and evaluation, highlighting
the need for heuristic agents. In simple configurations such as one-host and two-
host systems with network validity monitors only, the action space is small and
paths to terminal states are short, allowing random agents to cover most relevant
behaviors and learn an accurate model of the system. However, in the four-host
configuration, behaviorally critical transitions become rare and difficult to reach
through random exploration alone. Consequently, models trained with random
agents tend to capture common behaviors while failing on valid but infrequently
observed edge cases. This limitation becomes especially apparent under heuristic
evaluation, where random-trained models generalize poorly compared to mod-
els learned from heuristic-driven traces. These results indicate that as systems
scale, random exploration fails to adequately exercise the full state space, and
exploration strategies that deliberately target meaningful behavioral sequences
become essential for learning accurate and robust models.

whether the traces provides meaningful signal. If nearly all actions in the traces
succeed, then a trivial model that always predicts “success” would achieve arti-
ficially high accuracy. To validate that our sets are non-trivial, we measured the
proportion of failed actions using 500 200-step traces across all configurations,
