# Projection cache review

The store interns each distinct (parent, symbol) prefix node and maps a requested mask from the cached superset with minimum (bit count, numeric mask). Iterative parent traversal and per-request memoization avoid recursion and transform each encountered source node once. Canonical node IDs give exact word identity, so first-positive witness and rejection-mask membership preserve duplicate ordering. Empty words and samples are represented directly. The supplied tick is called during construction, transformation, materialization and sample scans; an interrupted entry is not published to the cache, although already interned nodes and counters may remain.

At the current integration boundary, `optimizer.py` passes projected positive/negative lists to `MainTeacher.check` under the same block-keyed `images` interface. `teacher_main.py` consumes those lists and does not import or inspect the projection implementation. The optimizer separately uses the rejection mask for coverage and the first-positive map for cut witnesses; bit i denotes a negative projection absent from all positive projections. This review checks that interface and source structure, not a proof that historical implementations are byte-for-byte identical or a full solver validation.

`projection_tests.py` compares every mask to an independent direct scanner, including three query orders, epsilon, empty classes, duplicate words, Unicode, prefixes, and 5,000-symbol traces. Its tie-break case and repeated-query counter check exercise cache behavior. This is finite testing, not a complexity or correctness proof.

`projection_benchmark.py` compares a fresh per-run dictionary-cached naive scanner with a fresh store. It generates fixed repeated-prefix positive and negative samples for 4 and 8 symbols, uses deterministic distinct and repeated query sequences of at most 64 masks, and repeats each case three times. JSONL includes corpus hashes, all mask queries, construction/query/total times, result and rejection checksums, and counters. Full result and rejection checksums must match before rows are written. Both methods include checksum work in query timing; store construction includes initial full-mask projection, while the naive construction is an empty cache. The benchmark excludes the solver, teacher, deadline callback cost, memory measurement, and general workload representativeness. Each new store mask still requires transformation and materialization; these measurements do not establish a universal speedup. Output creation is exclusive to preserve existing evidence.
