# C030 proposal freeze: two complementary full-contract optimizations

Status: candidate proof for independent review; no implementation, source freeze, experiment, or speed claim yet. Biggest overlooked point? Maximum-only solvers and merely feasible witnesses do not satisfy C028's exact family counts, two lexicographically first global witnesses, and two first optimal witnesses.

## Scope, baseline, and contract

Baseline is the frozen C028 `results/2026-11-11/exact_foundations_v28/implementation/reference.py` (SHA-256 `5f60b27447b37ec07f1fd6bce75be6199b898573d4b32e90413e900e3a615a94`) together with SPEC and both amendments. One input record has exactly `alphabet`, `positive`, `negative`, each word an array of atomic nonempty IDs; normalization, validation, contradictions, empty alphabet, epsilon, unused IDs, and malformed input are unchanged. The complete contract includes exact all-compatible count C, exact optimum count O, max block count, all-K status, lexicographically least optimal RGS in declared alphabet order, first up to two global and optimal witnesses, finite H factors in normalized first-positive-projection order and first rejecting block for each normalized negative, null mathematical fields for incomplete/invalid/error. Counts refer to partitions, not machines. Python's `max_candidates` is optional and controls enumerated candidates, not target state count or a data restriction.

Conformance means exactly equal completed fields/witness serialization and statuses on the same input and budget, barring environmental resource interruption. A particular externally timed interruption cannot be required to occur at the same instruction or produce the same progress; both solvers must handle caught interruptions and memory exhaustion by `INCOMPLETE` with null mathematical fields. A hard-killed process may return nothing. No optimization is allowed to use truth metadata, K, sample truncation, loss of exact ties, or unchanged-machine assumptions.

## Candidate A: singleton-compatible full-family certificate

After full validation and the existing contradiction check, and ONLY when `max_candidates is None`, directly test the singleton partition S = RGS `(0,1,...,m-1)` using the baseline criterion. If it is not compatible, do not draw any conclusion and fall back to enumeration. If it is compatible, compute exact Bell(m), construct the canonical first two global RGS and the one singleton optimum, materialize witnesses with the unchanged baseline witness constructor and verify them using the unchanged baseline witness verifier, then return the full result.

**Lemma A1 (coarsening).** If B subset D and n differs in B-projection from every positive, it also differs in D-projection from every positive; otherwise projecting a D-projection equality down to B would contradict the first inequality. Every partition is a coarsening of S. Since each negative has a rejecting singleton when S fits, that singleton is contained in some block of any partition and the block rejects the same negative. Thus all set partitions fit. For m=0, S is empty; it fits exactly if N is empty, and there is exactly one partition, the empty one. No nonempty-block assertion is applied to the empty alphabet.

**Lemma A2 (all counts and order).** The all-compatible count is the Bell number B_m. Compute exact B_0=1 and Stirling values by S(0,0)=1 and S(i,k)=S(i-1,k-1)+k*S(i-1,k), with out-of-range values zero, then B_m=sum_k S(m,k). This recurrence follows by placing the last symbol alone or into one of k existing blocks, and uses arbitrary-precision integers. Optimal block count is m and only the singleton partition has m blocks, including m=0; hence O=1 and `optimal_unique=True`. In declared order, the first global RGS is `0^m` (empty if m=0). If m>=2, the second is `0^(m-1)1`, because the lexicographically smallest nonzero position is the last. For m=0 or 1 there is no second partition. The optimal RGS is `(0,1,...,m-1)`. Status is UNIQUE_COMPATIBLE iff B_m=1, else AMBIGUOUS. Calling the baseline witness constructor with the first global and optimal RGS gives exactly the correct factors, normalized index ordering and replay indices; calling its verifier preserves the ERROR-on-failed-replay behavior. Every listed RGS is independently covered by Lemma A1.

**Budget rule.** Any supplied nonnegative `max_candidates`, INCLUDING 0, bypasses A and uses the baseline enumeration. Invalid `max_candidates` is validated first, just as baseline. Therefore an explicit budget still returns INCOMPLETE at exactly the same enumeration boundary as baseline (unless an already-proved contradiction returns INCOMPATIBLE), including when it equals Bell(m). Singleton checking must not occur before full input validation. If A encounters a caught resource interruption it returns the normal null-field INCOMPLETE, not a partial Bell count. The 0-alphabet negative-epsilon case does not pass the certificate and reaches ordinary enumeration, unless already contradictory. No early K or feasibility status is inferred from a failing singleton check.

**Cost.** If the certificate applies, its exact Bell calculation takes O(m^2) arithmetic operations and O(m) arbitrary-precision entries, plus singleton checking and at most three retained witness constructions/replays (some may be duplicate across lists). Bit costs and input lengths are not constant. This is a polynomial-in-explicit-input special case, not a general polynomial bound. On other data the precheck can add overhead. No general speed or memory improvement is asserted.

## Candidate B: bounded per-solve block rejection memo

For each block B encountered during exhaustive RGS enumeration, memoize its vector `R_B[j] = (pi_B(N[j]) not in {pi_B(p): p in P})` in a fresh per-invocation cache. The key is the tuple of whole string IDs in declared order, not concatenated text or characters. Use a deterministic bounded LRU of at most 256 block vectors; misses compute from all normalized positives and negatives, and eviction discards only cached values. Do not alter normalization, RGS enumeration, candidate budget checks, witness construction, verifier, counters, status, or ordering. Evaluate a candidate with block vectors in block-label order: it is compatible iff for each j at least one vector has true at position j. For no negatives this is vacuously true; for no blocks and at least one negative it is false. The memo is not shared between inputs or across solve invocations.

**Lemma B (extensional identity).** For fixed normalized P,N and B, R_B[j] is exactly the baseline test for whether B rejects N[j]. Its value is independent of the other blocks and of enumeration history. A hit, miss, or eviction therefore returns the same vector, and union coverage over all blocks is exactly the baseline `for each negative find a rejecting block` predicate. An identical acceptance Boolean for each RGS, in identical enumeration order, gives by the original C028 prefix invariants identical C, best, O, first-two global and optimal RGS and resulting witnesses. The unchanged baseline witness constructor selects the same first rejecting block and serializes projected positives identically; the cache does not serve witness outputs. Validation and budget logic remain as in baseline. The cache bound limits retained vectors, not alphabet size, samples, candidates or behavior. Captured KeyboardInterrupt/MemoryError must return INCOMPLETE with null fields, although overhead may cause resource failure in one implementation and not another.

**Combination and ablation.** One combined implementation may first use A when allowed and otherwise use B. For proof and attribution, A-only and B-only variants run the same full contract and are separately available for the fixed audit/ablation; no input/result-based variant selection is allowed. B need not preserve baseline's temporary allocation pattern or exact runtime, and may regress on small inputs; verify with measurements, don't infer. Lazy evaluation order must not skip an input validation or change budget candidate counting. Avoid externally visible cache state or memo reuse across solves.

## Relationship to prior work and rejected shortcuts

C026 already used forced-atom checks and rejection-mask reuse for its max-block DP, and C024 used sound atom and partition checks for different outputs. The present A/B candidates are straightforward reuse/adaptation for the fuller C028 contract; no novelty is claimed. Baseline RGS iteration and Bell/Stirling counting are standard combinatorics; see [Stamatelatos and Efraimidis, *Lexicographic Enumeration of Set Partitions*](https://arxiv.org/abs/2105.07472) and [NIST DLMF §26.7](https://dlmf.nist.gov/26.7). The closely related projection obstruction is described in [Henry et al., §4.1 and §6.1](https://arxiv.org/html/2504.16624v3), in their active, potentially overlapping-distribution setting; no equivalence of whole problem formulations is asserted. [Björklund, *Exact Covers via Determinants*](https://arxiv.org/abs/0910.0460) concerns special exact-cover decision problems and randomized methods, not this full counting/witness contract. It is context, not a drop-in proof. Counting one symmetry-orbit representative as one partition is unsound in general because output asks for labeled partitions and canonical first witnesses; no orbit quotient is adopted. Maximally refined does not mean maximum block count. This bounded literature check does not establish novelty or comprehensively survey all exact counting methods.
