# C028 specification amendment 2: witness serialization

This additive amendment clarifies the approved first-occurrence normalization and the concrete Python provider witness representation; it does not change the accepted input, mathematical model, search, source, or conclusions. The governing contract is `SPEC.md` plus amendments 1 and 2. Independent re-review is required; biggest overlooked point? Negative-witness positions must refer to normalized, not raw, duplicate-bearing input.

A witness is a record with `rgs`, `blocks`, `factors`, and `negative_rejected_by`. `rgs` is the canonical label array in input alphabet order. `blocks[i]` is the block with RGS label i, with symbols in input alphabet order. `factors[i]` is the finite factor H for `blocks[i]`, represented as an array of projected word arrays, deduplicated by first occurrence in the normalized positive list. There is one factor entry per block, including for empty factor languages; the empty partition has no factor entries.

Deduplicate positive and negative words independently while preserving the first input occurrence, as already specified. The length of `negative_rejected_by` is the number of normalized negative words. Its element j is the zero-based index into `blocks` and `factors` of the first block in label order whose factor excludes the j-th normalized negative's projection. Replaying every normalized negative proves rejection of all raw occurrences of that word as well. With no normalized negatives the list is empty. For Sigma empty, a compatible empty partition has all four arrays empty. These are sample witnesses, not recovered physical machines.
