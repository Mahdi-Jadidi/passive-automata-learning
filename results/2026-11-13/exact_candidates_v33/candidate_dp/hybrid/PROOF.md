## Composition and output proof

For every non-None `max_candidates`, directly call frozen C028 `solve` with the same arguments. This preserves candidate-prefix semantics, type/validation precedence, schema, contradiction handling and incomplete behavior. No structural shortcut or graph preprocessing executes for a budgeted call.

For unlimited calls, validate and normalize with frozen C028. A malformed record and a contradiction have exactly the C028 result and precedence. Call C030 `_certified_all`: it first checks the singleton partition. If compatible, coarsening proves every partition compatible; the existing helper constructs and verifies the full output, including Bell count, unique singleton optimum, canonical first two witnesses and factors. Thus return its result, including ERROR if replay fails. In the empty alphabet this check is sound by the empty-conjunction criterion; with a negative it fails.

If the singleton certificate fails, call frozen graph `_components` and `_expand` and evaluate the component partition against C028 `_candidate`. By the graph proof every compatible partition coarsens this partition. If it passes, every such coarsening is compatible, and no other partition can be compatible. Use frozen graph `_bell` and `_finish` with its canonical lifted first two component RGSs and unique optimum. The graph proof establishes expansion order even for interleaved components; `_finish` constructs and replays the same frozen C028 witness schema. A replay failure is ERROR. The graph certificate is conditional on that compatibility check; forced components alone are insufficient.

If that certificate also fails, call frozen DP `solve(data)` in full, not the graph exhaustive fallback. DP independently validates the record again and gives the exact contract with its own resource handling. All three successful branches therefore provide the same completed mathematical result and canonical serialization as C028; their selection depends only on exact compatibility/structural tests. Caught keyboard or memory exhaustion while preparing either certificate returns C028-shaped INCOMPLETE without partial mathematical claims. DP catches its own recursion exhaustion; hard kills or failures before import can produce no result. No physical identification or universal speedup follows.

## Costs and limitations

The hybrid repeats normalization before DP fallback, computes the singleton test and, if it fails, graph mandatory-set preprocessing and a component-partition check before the DP. It can therefore be strictly slower and consume more memory than DP alone. Imports and hash checks are outside `solve`; fresh-process timing must report both solve-only and startup-inclusive measures. Explicit budgets fall back to baseline, so the hybrid makes no speed claim for budgeted calls. The graph helper's local copy is hash-checked before import, but a race that changes files between check and loading is outside the stable-files experimental assumption. Worst-case DP remains exponential; no heuristic cutoff or altered pruning is introduced. The biggest overlooked issue is that the second shortcut is valid only when the entire component partition passes its compatibility test; finding forced edges alone never licenses Bell counting.
