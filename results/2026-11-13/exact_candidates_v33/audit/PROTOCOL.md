# V33 independent evaluation protocol — locked before candidate execution

Scope: compare C028 `solve`, C030 `solve_combined`, candidate DP and candidate graph using the **same full unlimited C028 serialized result**, not a maximum-only or output-only mode. The baseline and C030 frozen SHA-256 are `5F60B27447B37EC07F1FD6BCE75BE6199B898573D4B32E90413E900E3A615A94` and `7501901C6DE5D7BB78FFC60F152B818733E3BD4460C9A655B8D783F384E8FC2B`. Python: bundled CPython runtime; record exact version, OS, commands and hardware on official run. Candidate source and proof hashes must be frozen and reviewed independently before any official candidate invocation; any replacement is a new explicitly recorded repair round (at most two per concrete defect). Do not silently combine rounds or discard failures.

Full contract: exact status, C, k*, O, optimal_unique, recommendation, first two canonical compatible and optimum witnesses, factor lists in first-occurrence positive-projection order, first rejecting block indices for first-occurrence normalized negatives, and null semantics for INVALID_INPUT, INCOMPLETE and ERROR. Compare entire objects, not selected values. Validate schema, IDs, labels, partition coverage, canonical RGS, first witness order, factors and rejection index by independent replay; no string concatenation of atomic IDs. Infeasible means C=O=0, absent k*/recommendation, empty witness lists. A computation resource cap is not infeasibility and produces no exact mathematical claim. Candidate budget work units must preserve baseline `max_candidates` semantics if claiming baseline API equivalence; unsupported budget behaviour is reported as a limitation, never ignored.

Independent oracle `insertion_oracle.py` SHA-256 `AB49BC6F2C9B87DC4A1AA4BB7FDE8134069615E71051614224C6603C148A7EFC` recursively inserts an ID into an existing/new set block and tests tuple projections directly; it does not share candidate DP recurrence, graph reduction, or the baseline's RGS generation. Canonicalization and serialization occur after enumeration. Self-test verifies Bell(0..8) and distinct RGS, key empty/epsilon and opaque-ID examples. Cross-check normalized full output with baseline and both candidates; independently replay. Include checker mutations of counts, RGS, order, and rejection indices; failing mutations falsify checker validity rather than count as candidate failures. The oracle is a bounded falsification tool, not a mathematical proof.

Correctness corpus `correctness_cases.jsonl` SHA-256 `294B48B80DF5A15AA95DEBBBD14677FB26211DDB86E81EF0EE44AA29F5282927`: 2,187 complete ternary labellings of seven words over {a,b} of length at most 2; 60 deterministic seeds from C028 oracle for m=3..8; 24 prior fixed cases (including epsilon/m=0, contradiction, duplicates/order, unused and opaque IDs, ties and collision IDs); four explicit original/renamed/duplicated/unused-ID metamorphic records. Test duplicate and bijective-ID rename invariance of serialized counts/RGS and transformed factors; use oracle for unused-ID effects. Separately run invalid schema and budget boundary cases (including 0,1,Bell(m)−1,Bell(m), contradiction, bool/negative/float invalid budgets). Timeouts/errors preserved with input ID, exception/traceback, stdout/stderr and source hashes.

Frozen timing corpus `timing_cases.jsonl` SHA-256 `013E2B60DC1D5740D766A9B0F77C458C4FBB92F203EE67977F3FE7104B48215B`: ten synthetic cases including all-compatible m8/m10, one-block-only adjacent swaps m8, tied optimum, overlapping negative coverage, reverse/order constraints m9/m10, repeated projections m9, long words m4, and many traces m3. These are synthetic; no claim about real traces. Generator SHA-256 `F5C580E21B03B1632D1486F5B2AA36E75170610882CF4185ABBC45E92F8D24D6`. Purposes are hypotheses, not independently verified measured instance statistics; check and report actual counts when known. Freeze corpus hashes before timings; never select or modify cases after observing results.

Correctness gate precedes official timings; report any mismatch and stop promotion of that frozen version. For each qualifying solver and each fixed case, exactly three separate child-process trials, unlimited candidate budget and a 20-second outer wall cap, same input and full output. Fixed deterministic cyclic solver ordering, same host with no deliberate concurrent load. Child starts its `perf_counter` immediately before `solve` and ends immediately after: includes all per-solve preprocessing, reconstruction and replay inside the solver; excludes imports and JSON serialization. Parent also records startup-inclusive elapsed and OS exit status. Parent captures bounded stdout/stderr, exact source and corpus hashes, trial ID, output digest and full output or separate output artifact. Timeout is censored (≥ cap), never a numeric solved time; no ratios using timeouts. Check successful outputs agree across solvers before treating them as comparable. Report every raw run and per-case medians only for three successful comparable runs. Startup inclusive timing can reflect serialized-output cost and OS scheduling. Memory not reported without a consistent trustworthy measurement method. No reruns chosen on speed, no universal speed claims. Host thermal/load/interference and startup dominate short runs; bounded sample timings do not prove asymptotic behavior or universal correctness.

Biggest overlooked issue: a fast candidate producing only an optimum, or silently changing ordering, budget, serialization, or rejection-index semantics, is not solving the measured full-output problem.
