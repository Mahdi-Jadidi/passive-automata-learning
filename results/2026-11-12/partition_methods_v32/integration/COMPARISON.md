# Comparison of fourteen method families

**Integration release candidate — dossier reviews passed; independent integration review pending.** m=|Σ|, n=|N|, L is explicit input length. All exact claims assume validated input, sufficient resources, completed proof or enumeration, distinct-partition counting, canonical RGS ordering and witness replay. The shared edge conventions are in [the report](REPORT_EN.md#model-and-exact-contract). PROVED is scoped to the named construction; REFUTED-SPECIFIC concerns only the described procedure; OPEN is unresolved, not impossible.

## Graph index

| Scenario | Formulation | Main conclusion |
|---|---|---|
| Forced-pair/atoms | Pairwise sufficient must-link tests followed by compatibility of atom partition | Certificate gives all coarsenings; failure does not show infeasibility. |
| Candidate-block conflict and coverage | Independent set of disjoint candidate subsets plus symbol and negative coverage | Exact bijection with side constraints; exponential representation. |
| Minimal rejecting hypergraph | A negative is rejected when a block contains a minimal rejecting subset | Exact, potentially exponentially large; do not count witnesses as partitions. |
| Classical cover/independent set/coloring/clique cover/cut, including bipartite | Specific edge-to-positive-word construction | k*=α+1; bipartite restricted value is polynomial; general direct simplification and count claims require proof. |
| Auxiliary-node encoding | Polynomial projection circuit → CNF → clause-occurrence independent-set decision graph | Decision equivalence; a parsimonious single-instance standard objective is OPEN. |

See [five graph scenarios and proofs](REPORT_EN.md#five-graph-scenarios). The largest overlooked issue is the difference among feasibility, exact optimum, counting all compatible and optimal partitions, ordering witnesses, and physical recovery.
