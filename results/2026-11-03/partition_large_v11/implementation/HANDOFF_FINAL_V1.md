## Changes from C010

- Replaces the all-positive/all-negative adjacent-swap pair scan with an RLE
  index of maximal two-symbol intervals. Every indexed candidate retains its
  full collision bucket and is verified against exact context, interval
  support, and per-symbol counts before contraction.
- Keeps `swap_edge_witnesses` restricted to adjacent swaps and adds
  `binary_interval_must_link_certificates` for replayable contextual
  two-symbol anagram intervals.
- Retains exact C010 atom-feasibility checking and atom-coarsening Bell/DP
  search, while adding bounded projection reuse and canonical witness reuse.
- Adds counters for RLE/indexing, exact verification, projection-cache
  activity, and witness-cache activity. These diagnostic fields do not
  establish a speedup.

The frozen proof in `../theory/RLE_INTERVAL_INDEX_PROOF_v1.md` maps as follows:

- **R1–R2:** maximal windows generated by grouping identical unordered
  adjacent RLE transition labels; candidate-generation bounds only.
- **R3–R4:** aligned maximal intervals discover every contextual T1 witness;
  retaining all fingerprint candidates and verifying exact contexts handles
  collisions and preserves T1 pair-edge completeness.
- **Certificate soundness:** a certified pair must co-own in every compatible
  factorization because separating the two symbols preserves each factor's
  projections for the certified positive/negative words.

Completeness is for T1 symbol-pair edges, not every semantic must-link or every
possible witness. Missing an edge is never interpreted as evidence that two
symbols can be separated; the exact partition search remains authoritative.

## Counter meanings

- `total_input_characters`: sum of lengths of deduplicated positive and
  negative words; `atom_projection_checks`: negative words checked against
  all contracted atoms.
- `fingerprint_characters`: characters used to build rolling prefix data.
- `rle_runs`, `binary_windows`, `binary_window_characters`: RLE runs, maximal
  indexed two-symbol windows, and their total span lengths.
- `positive_interval_records`, `legacy_swap_interval_records`,
  `fingerprint_buckets`, `non_singleton_fingerprint_buckets`: index size and
  bucket diagnostics.
- `interval_index_candidate_checks`, `swap_pairs_tested`: candidate records
  visited in interval and legacy-swap indexes; they are not the C010 Cartesian
  positive-negative pair count.
- `exact_context_checks`, `exact_context_characters`,
  `fingerprint_collision_contexts`, `interval_characters_verified`,
  `exact_interval_rejections`: exact verification work and rejected
  fingerprint candidates.
- `binary_interval_certificates`, `successful_unions`, `swap_edges`:
  interval certificates emitted, successful DSU merges, and retained legacy
  adjacent-swap witnesses.
- `projection_cache_hits`, `projection_cache_misses`,
  `projection_cache_evictions`, `projection_characters_scanned`: projection
  LRU behavior. The LRU holds at most 4096 entries, not 4096 bytes; actual
  memory depends on word and projection lengths. Empty-block projections
  bypass the cache counters.
- `partition_witness_cache_*` and `projection_witness_cache_*`: canonical
  partition and full projection-witness memoization within the solve call.
- `block_masks_computed`, `dp_states`, `dp_branches`,
  `enumerated_partitions`: lazy rejection-mask evaluations, exact DP states
  and branches, and output family size when enumeration is requested.
- `preprocessing_seconds`, `search_seconds`, `provider_seconds`: internal
  phase timers with C010 boundaries; they are not interchangeable with
  whole-process elapsed time. `provider_seconds` excludes final representative
  witness construction.

`provider_seconds` keeps the inherited C010 timer boundary and is assigned
before final representative witness construction. Use captured whole-process
wall time for comparisons. The RLE index does **not** imply a general linear
end-to-end bound: fingerprint collisions, exact common-context verification,
fallback partition search, witness construction, output expansion, and JSON
serialization can dominate. Output and memory costs must be measured
separately; no timing, output-size, or memory results are included yet.

## API caveats

Treat the Python result object as read-only: nested partition lists may be
shared across witness fields. CLI JSON serialization still expands every
field. Input validation precedes the cooperative deadline checks, as in C010.
